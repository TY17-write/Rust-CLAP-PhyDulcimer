01この音源が何であるか

手法の選定は 研究ノート に譲る。結論だけ書くと、 打弦弦そのものの合成は隣の Rust-CLAP-PhyPiano と同じモーダル合成 (並列2次共振器バンク) で、 理由も同じ — 部分音の周波数を直接置けること。 したがって modal.rs / hammer.rs / soundboard.rs と検証ツール一式は、そのまま資産になる。

本プロジェクトの中身は、ピアノと構造が違う 4 か所だけである。残りは移植と再校正になる。

ピアノ (PhyPiano)ダルシマー (本プロジェクト)
ボイスプールから確保し、ノートオフでダンパーが止めるダンパーが無い。全弦を常時回す。打撃はボイスの確保ではなく力の注入
1 本の弦 = 1 つの音高ブリッジが弦を 2:3 に分け、1 本が 2 つの音高を持つ (完全5度)
打弦点は固定 (x/L = 1/8)奏者が打弦点を選ぶ (x/L = 0.05–0.15)。主要な音色操作
出力は無響。空間は DAW 側の仕事X-Y ステレオで録られた部屋まで含める。楽器の幾何と部屋を同じ座標系で持つ

やらないこと

  • 板・空気の有限要素シミュレーション。響板はフィルタ近似
  • 実測 IR の畳み込み。差し替え余地はインタフェースに残すだけ
  • 特定の個体の再現。設計則から導いて文献値の範囲と照合する
  • ツィンバロム / サントゥールの作り込み。配置表の差し替えで後から乗せる

02楽器の物理

実測研究 (Peterson 1994 / 2006、Vongsawad et al. 2014) と製作者の資料から、 モデルの構造そのものを変えるほどの違いを拾う。どれもピアノ音源のパラメータ変更では届かない。

ブリッジが弦を 2 つの発音区間に分ける

トレブルコースは両端のサイドブリッジに加え、中央のトレブルブリッジをまたぐ。 ブリッジ位置が振動長を 2:3 に分けるので、左右の区間は完全5度の関係になる。

ピアノのデュープレックス・スケーリング (アリコート) と同じ構図だが、 ピアノでは副次的な色づけであるのに対し、ダルシマーでは主たる発音区間が 2 つある。 バスブリッジも弦を分けるが比は単純でなく、長い側だけを演奏に使う。使わない側も張られたままなので共鳴はする。

ダンパーが無い

アメリカ式ハンマーダルシマーには消音機構が一切無い。 Peterson は、製作者がこの長すぎる減衰を短くするために 「ブリッジキャップの変更・ブリッジのスロット加工・重量と剛性の低減・響板インピーダンスの低減」を試みてきたと記している。 楽器設計上の課題として認識されているほど鳴り続ける。

  • ノートオフが無い。MIDI のノートオフは基本的に捨てる
  • ボイス割当が要らない。打撃は既に振動している弦への力の追加であって、ボイスの確保ではない
  • 共感共鳴が主役。ピアノではペダルを踏んだときだけの現象が、ここでは常時

打弦点が固定されない

ピアノのハンマーは常に同じ位置を叩く。ダルシマーは奏者が叩く位置を選ぶ。 典型はブリッジから 1–2 inch (25–50 mm)。区間長が 330–495 mm なので比にして x/L ≈ 0.05–0.15、 ピアノの 1/8 (0.125) よりブリッジ寄りまで動く。ブリッジ寄りほど明るく打楽器的に、離れるほど丸くなる。

Peterson の指摘 — アタックの正体。 ハンマーが接触している短い間、打弦点とブリッジに挟まれた短い区間が独立に振動して、弦の基音よりはるかに高い周波数でブリッジを叩く。 x/L = 0.05 ならこの区間の基本周波数は弦の 20 倍。 モーダル合成では励振の重みが sin(nπ·x_h/L) なので原理的には自動で出る — ただしモードを十分な本数まで持っていればの話で、モードの打ち切りが直接アタックを殺す。

ハンマーが硬くて軽い

木 (メイプル・チェリー・オーク・ウォルナット) の棒。裏表で材質を変え、片面は素の木、もう片面をレザーやピアノフェルトで覆うものが多い。 奏法は「drop and bounce」— 6–12 inch の高さから落として重力で当て、素早く跳ね返して接触時間を最小化する。

ピアノのフェルト (接触 0.5–4 ms、圧縮すると硬くなる強い非線形) とは別物で、ほぼ剛体接触に近く接触時間が桁で短い。 接触時間が 0.1–0.3 ms なら 48 kHz で 5–14 サンプルしかなく、 PhyPiano の 4 倍オーバーサンプルでは足りない見込み。P1 で実測して決める。

楽器の諸元

特定の個体の実測ではない。公開資料から拾った代表値で、設計則から導いて文献値の範囲と照合する方式を採る。

03モデルの構造

中核 1 — ボイスプールを廃す

弦は楽器の固定資産として起動時に構築し、process のたびに全部回す。 note_on は「どの弦のどの区間を、どの位置で、どの強さで叩くか」を決めてハンマーを 1 つ起動するだけで、弦の状態はリセットしない。

  • ボイス割当・ボイス盗み・ノートオフの処理が丸ごと消える
  • 連打で鳴っている振動に足し込まれるのが自動的に正しくなる。ロール奏法はこの楽器の主要奏法なので効く
  • 共感共鳴を別に持たなくてよい
振幅が閾値を下回った区間はスキップする。ただし性能はスキップを当てにせず最悪ケースで設計する — ダンパーが無い楽器では、演奏中ほぼ全区間がアクティブになる。

中核 2 — ブリッジで結合された 2 区間

固定端モードで両区間を持ち、ブリッジ点の速度 v_b を介して結合する。 ブリッジ点は両者の端なので変位モードは 0 だが、端点が動くときの結合は変位ではなくモード形状の傾き φ′_n ∝ n で決まる。したがって:

  • ブリッジ点の速度が各モードを ∝ n の重みで駆動する
  • 各モードはブリッジに ∝ n の重みで力を返す
  • 両区間と響板のアドミタンスが v_b を共有する

結合はモーダル空間でランク 1 なので、各サンプルで「v_b を作る内積 (O(N))」→「v_b を配る外積 (O(N))」の 2 パスで済む。 共感共鳴・縦振動と同じ構造で、PhyPiano で既に動いている形。

結合が高次ほど強いことは、Peterson の観察と一致する — 短い区間が高い周波数でブリッジを駆動するという現象が、この係数から自然に出る。

段階形安定性
A打った区間 → 反対の区間への一方向無条件で安定 (PhyPiano の共感共鳴と同じ判断)
Bブリッジ点を共有する双方向。1×1 の陰的解陰的に解けば安定。反復は要らない。要検証

段階 A で音として成立させてから B に進む。 段階 B は PhyPiano が「やるとすれば弦のインピーダンスまで含めた双方向結合へ進むほうが筋が良い」と書いた、まさにその一歩。 ダルシマーではこれが楽器の本質なので避けて通れない。

中核 3 — 打弦点を演奏パラメータにする

x_h/L を実行時に変える。励振の重み sin(nπ·x_h/L) を打撃のたびに計算する。 既定 0.09 (ブリッジから約 40 mm)、可変範囲 0.03–0.30。MIDI CC で連続に動かし、ベロシティで少し寄せる (強打はブリッジ寄り)。 ハンマーの当たり面 (木 / レザー / フェルト) も切り替える。

note_on のコストが増える。sin をモード数ぶん計算するので、低音の 128 モードで無視できない。 PhyPiano の実測は低音 3.9 µs。着手時にベンチで測り、足りなければ位相の漸化式で 1 モードあたり乗算 2 回にする。

響板・箱・弦の配置

  • PhyPiano の soundboard.rs (並列2次バンク) を移植して再校正。ブリッジ 2 箇所で系統を分ける — PhyPiano のゾーン分割は分解能不足で負けたが、こちらは 2 箇所に物理的な根拠がある
  • ヘルムホルツ共鳴 + 板の最低次モードの 2 自由度結合を足す (音孔と箱)。Vongsawad らは音孔が放射音に強く効くことを示している
  • 弦ごとのブリッジ力ハイパスは移植する
  • 配置は layout.rs に表で持つ。既定は 15/14 の D/G 全音階。同じ音高が複数の場所に存在するので MIDI からの割当は 1 対多
  • E3–E6 の半音階配置 (37 音) も表として持つ。クロマチックダルシマー (Dusty Strings Chromatic 系) も一般的な実機で、全音階の欠落が無い。設計則は同じものを使い、音域で 3 バンク (バス / トレブル右 / 左) に割り付ける。切り替えはプラグインのパラメータで、弦バンクの再構築を伴うので activate 時 (または両バンク事前構築) に行う — 実装は P7
ブリッジ位置が 2:3 なら 5 度は純正 (702 cent) になる。平均律の 700 cent とは 2 cent 違う。 実機の調律師は左右が両方合うようブリッジを動かす。ブリッジ位置をパラメータにして純正と平均律の間で選べるようにする — これは物理から出てくる調律であって、後付けの機能ではない。

04ROOM — X-Y ステレオ

物理モデルの出力は「無響室でブリッジ力から作った音」であって、そのままでは楽器に聴こえない。 実機の音は必ず部屋を経由している。 汎用リバーブを後段に足すのでは楽器の各部が空間のどこにあるかという情報が失われるので、 楽器の幾何と部屋を同じ座標系で持つ。だから最初から設計に入れる。

なぜ X-Y なのか

X-Y は 2 本の指向性マイクを同一点に置き、軸を開いて構える方式。 その結果、この方式には他のステレオ方式に無い性質がある。

  • L/R に時間差が生じない。位相干渉が無く、モノ互換が保たれる
  • 定位はすべてレベル差で作られる (強度ステレオ)
  • 幅は控えめ。90° カーディオイドでは、軸方向の音源でも L/R 差は約 5–6 dB にしかならない
物理モデルとの相性が選定理由。 X-Y は L/R 間に遅延差を作らないので、弦の共鳴・ブリッジ結合・箱が作る微細な位相構造をそのまま通す。 AB (スペースドペア) は時間差でこれを濁す。せっかく物理で作った位相を、録音方式で壊さない。

3 層で組む

層中身X-Y であることの現れ方
直接音 響板の系統ごとに角度 θ と距離 d。カーディオイド p(θ±φ/2)、距離減衰 1/d、空気吸収 L/R 間に遅延差を作らない。差はレベルだけ
初期反射 部屋の寸法から鏡像法で 12–20 タップ。各タップに遅延・減衰・高域減衰・到来角 ここに一番出る。到来角ごとに同じカーディオイド行列を通すので、レベル差の時間パターンが空間になる
後部残響 FDN 8 ライン。帯域ごとの減衰 L/R の相関を高く保つ (既定 0.6–0.8)。同一点収音だから。無相関にすると AB になってしまう
後部残響を無相関にしないことが、この ROOM の最も間違えやすい点。 市販リバーブの多くは L/R を無相関にして広がりを作る。それは離して置いた 2 本のマイクの音であって、X-Y ではない。 FDN の出力を 2 つの異なる線形結合で取り出し、結合行列で相関を設計する。

検証 — ここは参照音源なしで数値が閉じる

本プロジェクトは参照音源を持たない (§10)。 その中で ROOM は理論値と突き合わせられる数少ない部分なので、指標を厳密に置く。

  • L/R 相互相関のピークが遅延 0 にあること。X-Y の定義そのもの。ずれていたらどこかで遅延差が入っている
  • モノ和 L+R がコムフィルタにならない。帯域の谷が −3 dB 以内
  • 相関係数 — 直接音区間で 0.9 以上、残響区間で 0.5–0.8
  • 音源角を振ったとき、L/R レベル差が p(θ±45°) の理論値と 0.5 dB 以内で一致
  • RT60 が設定した部屋と帯域ごとに一致。ITDG (直接音から最初の反射までの間隔) が部屋の寸法と整合
部屋を入れると楽器のモデルの粗が隠れる。 PhyPiano では響板の残響 0.3 秒が「どんなに速く弦を止めても音はここまでしか速く消えない」という下限を作り、測定を頭打ちにした。 ROOM はそれよりずっと長い。P6 より前の音質判断・P10 の追い込みは、必ず ROOM を off にして行う。

演算量は初期反射 20 タップ × 2ch と FDN 8 ラインで 3–5 µs/block。全体の 3% で、設計上の制約にはならない。

PhyPiano の 32 音同時 (183 µs, CPU 13.7%) とほぼ同じで、しかもこちらは全弦が鳴っている最悪ケースの値。 音域が狭く弦が短いぶんモード数が少ないので、ピアノより有利になる。前提が 2 つある。

  1. モーダル共振器の SIMD 化 (PhyPiano Phase 7 の f32x8) を移植すること。スカラのままなら 5〜10 倍で締切に当たる
  2. モード上限 128 が音色として足りること。打弦点がブリッジに近いので足りない可能性がある。足りなければ上限を上げるか、高域を残差合成に回す

P10

音色の追い込み — 参照音源を持たない前提で

PhyPiano は Phase 8 まで終えてから参照音源と並べ、Phase 9・10 を丸ごと追加することになった。 同じことが起きるので枠を置く。ただし本プロジェクトは参照を持たないので --compare が使えない。 代わりに参照なしで測れる指標を先に用意する。

見るもの判定の基準
音域間の一貫性隣接コースで明るさが急に飛ばない
減衰の音域傾向高音ほど短い。逆転していないか
打弦点の効きスペクトル重心が単調。ノッチが追随
物理量の妥当性線径・張力・接触時間・B が文献値の範囲
過渡と定常の比打撃音が音そのものより大きくないか

運用ルール

  • 測定は必ず ROOM off。部屋は粗を隠す
  • 音色の判断はユーザーの試聴に頼る。ただし耳の指摘をそのままパラメータに反映しない — まず上表のどれが動いているかを測ってから触る

08検証方法

PhyPiano の「測って確かめる」をそのまま引き継ぐ。指標を先に作ってからモデルを触る。

単体テスト

  • モーダル周波数・T60・打弦点ノッチ・接触時間の物理レンジ
  • 連打で振幅が足し込まれる (弦がリセットされない)
  • ブリッジ結合が 60 秒でエネルギー発散しない
  • ROOM の L/R 相互相関ピークが遅延 0
  • process のアロケーション 0

オフライン検証

  • --peak 0 を付ける。既定の正規化で A/B の差が消える (PhyPiano の頻出事故)
  • A/B フラグ — --no-room / --no-bridge-coupling / --no-cabinet / --strike-point / --hammer / --strings
  • --modulation (帯域包絡の変動深さ) — うなりはここにしか出ない
  • --correlation — L/R 相関と相互相関のピーク位置

性能

  • criterion。最悪ケース (全弦アクティブ) を測る。平均ではない

09危険

着手前に分かっている、計画を壊しうるもの。

内容対処
大 モードの打ち切りがアタックを殺す。打弦点が x/L = 0.05 まで寄るので第 20 部分音まで強く励振される。上限 128 で足りない可能性 P1 で上限を振って測る。足りなければ上限を上げる (演算量に余裕がある) か、高域を残差合成へ
大 参照音源を持たない。「参照より何 dB 暗い」で判断できない。PhyPiano が音質の追い込みで使った主要な梃子が無い 物理量が文献値の範囲に入ることを唯一の外部基準として厳守する (P1 / P3 の完了条件)。音色の判断はユーザーの試聴
大 ブリッジ双方向結合の安定性。ループを閉じるので発散しうる 段階 A で音を成立させてから B。B は陰的解のみ。エネルギーの単調性をテストで固定
中 ROOM が粗を隠す。残響は測定の分解能を奪う。PhyPiano では響板の 0.3 秒でさえ測定を頭打ちにした P6 以降も音質判断は必ず ROOM off。--no-room を既定にする案も検討する
中 ヘッドルーム。ダンパーが無く全弦が鳴り続ける。さらに残響が乗る。ピアノより厳しい 物理を曲げない。校正の基準を「ff のロール」に置き、出力段のソフトクリップで受ける
中 オーバーサンプル倍率。硬いハンマーは 4 倍では解けない見込み P1 で 4/8/16 を実測。倍率はハンマー面ごとに変えてよい
中 配置表の一次資料。15/14 の音の並びは資料により差がある 表駆動にして差し替え可能にする。特定の 1 台に合わせない
小 note_on のコスト。打弦点可変で sin をモード数ぶん計算する ベンチで測る。必要なら位相漸化式
小 GUI の埋め込みは DAW でしか検証できない 自動化しない。ユーザーに確認を依頼する
